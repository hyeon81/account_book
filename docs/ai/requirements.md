# 가계부 AI 요구사항 원문과 작업 계획

첨부 이미지에서 확인한 요구사항을 보존하고, 교육용 AI 에이전트 설계 문서의 범위와 완료 기준을 정한다.

## 요구사항 원문

```text
문서화에는 docs 폴더에 ai 폴더를 만들고,
가계부에서 사용할 만한 ai를 문서화해보자. 커밋하면서 진행해주고,

지금 내가 생각하는 것들은,

1. 카테고리 고르기 by AI - [Pasted text #1 +4 lines]
2. AI 채팅을 통한 통계 알림 - 가령 "저번 주에 내가 간 카페 횟수" 조회하는 그런 AI 채팅 통계
3. AI 기반의 통계 - AI 기반의 룰들을 만들어서, AI로 하여금 상황에 맞는 통계를 만들도록

이런 내용들인데 ai 에이전트 기반으로 각각의 내용들에 대해서 문서화하고, 특히 처음 것은 rag 를 도입하는 방식으로.
교육용이니까.
```

`[Pasted text #1 +4 lines]`는 이미지에 표시된 원문이다. 생략된 네 줄의 내용은 제공되지 않았으므로 추정해 복원하지 않는다.

## 이번 작업의 범위

요구사항의 결과물은 `docs/ai` 아래의 교육용 설계 문서다. RAG 카테고리 추천, 채팅 통계 조회, 상황에 맞는 규칙 기반 통계를 각각 에이전트의 도구 사용 흐름으로 구체화한다. 현재 UI의 각본형 대역과 향후 실제 AI 동작을 구분하며, 이번 작업에서 서버·DB·모델 연동을 구현하지 않는다.

통계 알림은 사용자가 채팅으로 질문했을 때 결과를 받는 동작부터 다룬다. 예약 실행과 외부 메시지 발송은 별도 후속 기능으로 둔다. AI가 선택하는 통계 규칙은 허용된 지표와 조건을 조합하는 선언형 규칙으로 해석한다.

## 작업 순서

1. 현재 가계부 설계와 UI의 구현 상태를 확인하고 요구사항 원문을 기록한다.
2. 하위 폴더 문서의 링크·앵커·JSON 검증 누락을 회귀 테스트로 재현하고 검증기를 확장한다.
3. 공통 에이전트 책임과 RAG 카테고리 추천의 데이터·검색·추천·수정·평가 흐름을 작성한다.
4. 채팅 통계의 질문 해석, 기간과 횟수 정의, 집계 도구와 예시를 작성한다.
5. 규칙 기반 통계의 생성·검증·확인·실행·설명 흐름을 작성한다.
6. 문서 색인과 기존 설계의 연결을 추가하고, 각 작업 단위를 검증한 뒤 영어 명령형 제목으로 커밋한다.

## 완료 기준

- 세 기능마다 입력, 처리 흐름, 도구 책임, 구조화 결과 예시와 실패 처리가 있다.
- RAG는 검색 자료 준비와 검색 결과를 사용한 생성 단계를 모두 설명한다.
- 교육 실습은 모델·검색 대역으로 시작하고 실제 모델 연동을 후속 단계로 구분한다.
- 카페 거래 건수와 실제 방문 횟수, 서버 집계와 모델 설명의 차이를 명시한다.
- 규칙은 서버가 검증하고 계산하며 임의 SQL이나 생성 코드를 실행하지 않는다.
- 문서 검증과 `pytest`가 통과하고 새 의존성과 비밀값 없이 작업 단위별 커밋이 남는다.

## 읽기 시작

완성된 기능별 문서는 [가계부 AI 설계 색인](README.md)에서 찾는다.

## 추가 요구사항 원문 (2026-10-13)

첨부 이미지의 문구를 줄바꿈과 표현 그대로 옮긴다.

```text
ai 를 넣은건 좋은데, 추가로 하나만 더 넣자. plan and execute 나 react 같은 에이전트 흐름에
대한 것을 활용할 만한 것을 하나 만들어주고,

또 tools.md 를 만들어서 공통으로 사용할 만한 툴을 만들어줘.

그리고 mcp.md 도 만들어서 외부 ai 서비스에서 접근해서 처리할 수 있는 통로에 대해서도
만들어주고.
```

이미지의 `react`는 문맥상 웹 UI React가 아닌 ReAct 에이전트 흐름으로 해석한다.
사용자가 확인한 이번 범위는 기존 AI 설계 문서 확장이다. 실행 가능한 서버나 SDK를 설치하지 않는다.
별도 worktree의 `feature/agent-tools-mcp` 브랜치를 `develop`에서 만들고 기존 AI 문서 기반 커밋을 가져온다.
원래 작업 폴더의 미커밋 변경은 작업 대상에 포함하지 않는다.

## 추가 작업 계획

1. 원문과 범위, 작업 순서와 완료 기준을 먼저 보존한다.
2. Plan-and-Execute로 지난 두 주의 카페 지출을 비교하는 교육용 사례를 추가한다.
   계획 생성, 서버 검증, 의존 단계 실행, 근거 기반 설명과 중단 조건을 구분한다.
3. `tools.md`에 기존 세 기능과 새 흐름이 공유하는 도구의 입력·출력·권한·오류 계약을 정한다.
4. `mcp.md`에 외부 AI 호스트가 공통 도구를 발견하고 호출하는 어댑터 구조,
   로컬 실습과 원격 연결의 차이, 인증·사용자 범위·오류 처리를 정한다.
5. 색인·공통 구조·루트 README를 연결하고 문서 검증과 `pytest`를 실행한다.
6. 영어 명령형 제목으로 작업 단위별 커밋을 남긴다.

## 추가 작업 완료 기준

- 에이전트 흐름 하나에 사용자 사례, 계획 JSON, 도구 의존 관계, 결과와 실패 사례가 있다.
- 공통 도구 이름과 계약이 기존 RAG·채팅·규칙 문서와 일치한다.
- 외부 MCP는 같은 서버 유스케이스를 재사용하며 계산·권한을 별도로 구현하지 않는다.
- 도구 발견·호출·결과 JSON 예시, 로컬/원격 전송과 인증 경계가 있다.
- 모든 예시는 설계안이며 연결 가능한 서버 주소·실행 명령으로 오인할 정보를 제시하지 않는다.
- 문서 링크·앵커·JSON 검증과 기존 테스트가 통과하고 새 의존성·비밀값 없이 커밋한다.


## 웹 UI의 AI 태그와 위키 요구사항 (2026-10-13)

첨부 이미지 원문:

```text
docs/ai/ 폴더에 있는 것들 바탕으로, 지금의 웹 ui? 부분에 ai
태그를 붙여서 만들어줘. 어떤 기능들이 ai를 통해서 만들어지
는지 그리고 어떤 에이전트를 쓰는지에 대해서 있으면 좋겠
어.

상단 바의 오른쪽 끝에 위키 같은 것을 두어서, 에이전트를 어
떻게 쓰고 있는지, ai는 어느 부분에 들어갔는지 등을 html 같
은 걸로 문서화를 해주면 좋겠어.
```

계획: 기존 별도 worktree에서 화면별 AI 태그와 상단 오른쪽 AI 위키를 추가한다.
위키는 HTML로 렌더링되는 React 페이지이며 docs/ai의 기능·도구·MCP 설계를 설명한다.
카테고리 추천·채팅 통계는 입력 도우미에서, 규칙 통계·주간 비교는 대시보드에서 연결한다.
실제 각본형 미리보기와 후속 AI 설계를 상태로 구분하고 외부 모델 연동을 구현한 것으로 표시하지 않는다.
위키 주소로 직접 접속·새로고침·뒤로 가기가 가능해야 하며 기존 거래와 대화 상태를 보존한다.
새 의존성 없이 테스트·타입 검사·린트·빌드·화면 검증 후 커밋한다.
