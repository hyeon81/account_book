# 가계부 AI 에이전트 설계와 교육 실습

가계부의 카테고리 추천, 거래 채우기, 채팅 통계, 규칙 기반 통계를 정리한 설계 문서다. 거래 저장·권한·계산은 API 서버가 맡고, AI 에이전트는 검색과 도구를 통해 추천하거나 결과를 설명한다. 현재 실행 가능한 AI 기능은 거래 추가 폼의 채우기와 카테고리 추천이며, 채팅 통계와 규칙 기반 통계는 설계안이다.

## 현재 구현과 설계의 관계

현재 거래 원본은 [서버 거래 저장](../server-ledger.md)의 PostgreSQL 거래 테이블에 저장한다. 기존 localStorage 자료는 사용자가 명시적으로 가져오며 브라우저 백업을 유지한다. RAG 검색 자료와 임베딩은 PostgreSQL·pgvector에 영속 저장하며, 변경되지 않은 문서의 임베딩을 재사용한다. 거래 추가 폼의 **채우기**는 `/api/transaction-draft`를 통해 실제 OpenAI 호출을 사용하고, 카테고리 영역의 AI 추천은 `/api/category-recommendation`의 RAG 검색을 사용한다.

모델 없는 `/api/stats/frequency`와 `/api/stats/compare`는 확정 거래를 SQL로 집계한다. 필수 날짜·유형, 선택 필터, 계산·오류·응답은 [API 계약의 집계 절](../api-contract.md#구현된-집계-계약)이 기준이다. `/api/summary`는 이번 구현 범위에 없다. `ui/src/infrastructure/scriptedAssistant.ts`는 통계 채팅 화면에 남아 있는 각본형 대역이며 상대 기간 해석·통계 도구·대화형 모델·통계 규칙 실행은 아직 구현되어 있지 않다.

[전체 서비스 설계](../agent-account-book-design.md)의 `ui → server → agent` 구조와 LiteLLM 기반 모델 호출 계획을 따른다. 이 문서들의 내부 도구와 JSON은 후속 구현 제안이다. 현재 [API 계약](../api-contract.md)의 확정된 문서 범위와 섞지 않으며, 구현 시 계약과 테스트를 함께 갱신한다.

## 교육용 구현 순서

1. 합성 거래와 카테고리 정의를 준비하고 서버의 기간 계산·집계·초안 검증을 모델 없이 테스트한다.
2. 검색 도구와 모델 대역으로 세 기능의 정상·오류·확인 흐름을 검증한다.
3. RAG 검색을 연결하고 키워드 분류·검색 없는 모델·RAG 결과를 동일한 평가 자료로 비교한다.
4. 기존 LiteLLM 연동 계획에 따라 실제 모델 호출을 연결하고 스키마 지원을 확인한다.
5. UI에 근거, 적용 기간, 규칙 버전과 확인 상태를 표시한다.

현재 RAG 구현은 PostgreSQL·pgvector와 승인된 `psycopg[binary]`를 사용한다. 새 의존성이 필요한 후속 구현은 프로젝트 규칙에 따라 먼저 합의한다. 실습은 합성 자료로 시작하고 실제 금융 기록은 최소 필요한 필드만 모델에 전달한다.

## 추가 설계와 웹 UI

공통 도구·Plan-and-Execute·MCP는 후속 설계다. 공통 도구를 서버 유스케이스와 대역으로 검증한 뒤 계획 실행과 MCP 어댑터를 연결한다. 인증과 권한이 준비된 뒤 원격 연결로 확장한다. [추가 요구사항](requirements.md#추가-요구사항-원문-2026-10-13)을 참고한다.

상단 오른쪽 AI 위키와 안내 태그에서 구현 기능과 후속 설계를 읽을 수 있다. [AI 위키 UI](../ui_docs/ai-wiki.md)에 위치와 검증 범위를 정리했다.
