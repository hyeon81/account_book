# 리포트 목 UI

## 요청 원문

> 그리고 리포트 기능을 넣ㄱ고 싶어 리포트 메뉴를 넣어주고 mock ui를 만들어줘

## 구현 계획

1. 공통 탐색에 리포트 메뉴와 월 선택을 추가한다.
2. 저장된 거래의 월별 요약, 카테고리·주차별 지출과 전월 비교를 계산한다.
3. 빈 가계부에서도 예시를 체험하게 하되 예시 거래는 저장하지 않는다.
4. 계산 테스트와 화면·빌드를 확인하고 기능 단위로 커밋한다.

## 화면과 데이터

[공통 UI 설계](ui-design.md)의 리포트 메뉴다. 월 선택은 대시보드·거래 내역과 공유한다. `내 거래`가 기본이며 기록이 없으면 빈 거래 안내와 0원 집계를 표시한다. `예시 리포트`로 전환하면 선택한 달과 전월의 가상 거래만 사용한다. 예시는 실제 거래와 섞거나 저장하지 않는다. 두 모드 모두 월 이동을 지원한다.

- 월별 요약: 수입, 지출과 차액. 차액은 계좌 잔액이 아니다.
- 차액 비율: `(수입 − 지출) / 수입 × 100`. 수입이 0이면 계산 불가로 표시한다.
- 카테고리별 지출: 금액 내림차순, 전체 지출 대비 비중.
- 주차별 지출: 1–7일, 8–14일, 15–21일, 22–28일, 29일–말일. 달력 주와 다르며 마지막 구간은 실제 날짜가 있을 때만 표시한다.
- 전월 비교: 수입·지출·차액과 금액 변화. 전월 지출이 0이면 지출 변화율은 계산 불가로 표시한다. 전월 기록이 없으면 0원 표시 이유를 안내한다.
- 소비 이야기: 집계로 만든 규칙 기반 문구. 실제 AI 호출이나 서버 리포트 생성은 없다.

좁은 화면에서는 카드를 한 열로 배치하며 비교 표만 가로 스크롤할 수 있다. 금액과 비중은 텍스트로도 표시한다. 모드 버튼은 선택 상태를 보조 기술에 전달한다.

## 검증

`ui/tests/application/report.test.ts`에서 월별 필터, 전월 연도 변경, 분모 0, 윤년 말일과 예시 거래 유효성을 확인한다. 실행 방법은 [UI README](../../ui/README.md)를 따른다. 화면에서는 메뉴 이동, 빈 상태, 예시 전환과 월 이동을 확인한다.
