# 채팅으로 거래 채우기 목 UI

## 요청 원문

> 잠깐 다시 실제 ai 서비스를 붙이는게 아니고, mock 정도로만 붙이는거야. ai는 나중에 붙일거야. 아까 작업을 이어서 해줘.
>
> 그리고 여기는 카드문자로 채우기로 되어 있는데, 채팅식으로도 채울 수 있게 ui를 구성해줘.
>
> 가령 카드 문자를 넣고, 다시 읽기 이렇게 했지만,
>
> 오늘 오후 3시에 카페에서 5천원 썼어 하면 그걸로 입력이

마지막 문장은 첨부 이미지 아래에서 잘렸다.

## 구현 계획과 결과

1. 기존 각본형 목 도우미를 재사용한다. 실제 AI·외부 서버는 연결하지 않는다.
2. 카드 승인 문자와 거래 문장을 같은 채팅에서 처리한다.
3. `5천원`, `1만5천원`, `2.5만원`을 처리하고 금액이 여러 개이거나 잘못된 입력은 초안으로 확정하지 않는다.
4. 입력 도우미에서는 초안 카드를 표시하고 거래 추가 창에서는 아래 입력 항목을 채운다. 사용자가 확인·저장하기 전에는 거래를 기록하지 않는다.
5. 단위 테스트·빌드·린트·Python 테스트와 실제 화면에서 확인하고 커밋한다.

## 동작

입력 도우미에 카드 문자 또는 거래 문장을 전송한다. 거래 추가 창의 `채팅으로 거래 채우기`에서도 같은 입력을 받는다. `문장 예시`, `카드 문자 예시`는 입력창만 채우고 `문장 보내기`를 누르면 처리한다. Enter는 전송, Shift+Enter는 줄바꿈이다.

예시 문장은 오늘 날짜, 카페 지출 5,000원, 사용처 카페를 채운다. 오후 3시 표현은 메모에 보존한다. 현재 거래 모델은 시간을 별도 항목으로 저장하지 않는다. 추천 카테고리는 규칙 기반이며 직접 변경할 수 있다.

금액이 없으면 추가 질문을 하고 이어서 보낸 금액으로 초안을 만든다. 잘못된 카드 문자·금액은 안내하고 저장을 막는다. 분류하지 못한 카드 문자는 카테고리를 직접 선택한다. 거래 추가 창의 `직접 입력으로 계속`은 대화를 초기화하고 기존 입력 항목을 직접 수정하게 한다.

실제 AI의 자유로운 문장 이해나 기존 초안에 대한 임의의 대화 수정은 지원하지 않는다. 지원하는 새 거래 문장을 다시 전송하면 새 초안으로 채운다. 동작 근거는 `scriptedAssistant.test.ts`와 `cardMessage.test.ts` 회귀 테스트다.
