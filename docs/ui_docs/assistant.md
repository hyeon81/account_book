# AI 도우미 UI 설계

이 문서는 [UI 공통 설계](ui-design.md)의 AI 도우미 화면을 구체화한다. 서버의 대화 응답과 초안 확정은 [API 계약](../api-contract.md)을 따른다. AI는 거래를 직접 저장하지 않으며 사용자의 확인이 필요하다.

현재 AI 도우미 화면에는 실제 AI 대신 각본형 입력 도우미가 있다. 정해진 문장 패턴을 처리하고 브라우저에 저장된 거래로 합계를 계산한다. 거래 추가 폼의 채우기와 카테고리 추천은 별도 로컬 API에서 실제 OpenAI 호출을 사용한다. 아래 HTTP·초안 상태 계약은 전체 대화형 도우미를 서버에 연결할 때 구현한다.

## 화면 구조

```text
AI 도우미
├── 안내 문구·예시 질문
├── 이번 화면에서 주고받은 메시지
├── 질문 입력·전송 버튼
└── 응답 카드
    ├── 조회 답변 또는 추가 질문
    └── 거래 초안 요약·수정·확정
```

사용자는 한 문장으로 거래 등록 초안을 요청하거나 저장된 내역을 질문할 수 있다. 빈 화면에는 “오늘 점심에 12,000원 썼어”, “이번 달 식비 얼마야?” 같은 예시를 보여주되, 누르면 실제 요청이 나간다는 점을 분명히 한다. 메시지에는 사용자 입력과 서버 답변을 구분해서 표시한다. 초기 버전은 서버 대화 이력을 저장하지 않으므로 새로고침 뒤 이전 메시지 복원은 보장하지 않는다.

## 질문 입력과 답변

입력창과 `보내기` 버튼으로 `POST /api/chat`에 `message`를 보낸다. 공백만 있는 입력은 전송하지 않는다. 전송 중 상태를 보여주고 중복 전송을 막는다. 요청 실패 시 사용자가 입력한 문장을 보존하고 재시도할 수 있게 한다. 대화 장애 `503`에서도 [거래 입력 폼](transactions.md#거래-입력-폼)과 일반 조회로 이동할 수 있다.

응답 `kind`에 따라 화면을 구분한다.

| `kind` | 표시 내용 | 다음 행동 |
| --- | --- | --- |
| `answer` | 설명, 서버 집계값, 적용 기간·필터 | 질문 계속하기 또는 거래 목록 열기 |
| `clarification` | 부족한 정보와 추가 질문 | 답을 입력해 원래 문장과 합친 완성된 메시지 전송 |
| `transaction_draft` | 저장 전 초안과 AI의 설명 | 초안 수정 또는 확정 |

조회 답변의 합계는 서버가 제공한 수치를 그대로 표시한다. 조회 결과가 없으면 기록이 없다고 안내한다. 모델이 반환한 문장만으로 저장 완료나 거래 합계가 확정된 것처럼 표시하지 않는다.

## 거래 초안 카드

초안 카드의 첫 줄에 `저장 전 초안` 상태를 표시한다. 날짜, 유형, 금액, 카테고리, 사용처, 메모를 모두 보여주고 `수정`과 `거래 확정` 행동을 제공한다. 필수 정보가 빠졌거나 카테고리가 불분명하면 확정 버튼을 활성화하지 않고 필요한 입력을 안내한다. 수정은 [거래 폼](transactions.md#거래-입력-폼)과 같은 필드·검증 방식을 사용한다.

사용자가 확정하면 `POST /api/drafts/{id}/confirm`에 수정된 필드만 `changes`로 보내고 `Idempotency-Key`를 함께 보낸다. 같은 확정 시도를 재전송할 때는 같은 키를 사용한다. 서버의 성공 응답에서 `transaction_id`를 확인한 뒤에만 `저장 완료`로 전환한다. 그 후 거래 목록과 해당 월의 합계를 갱신한다. 확정 전 초안은 목록과 합계에 넣지 않는다.

| 확정 결과 | UI 처리 |
| --- | --- |
| 성공 또는 동일 요청 재시도 성공 | 거래 ID와 저장 완료 상태를 한 번 표시하고 중복 거래 카드를 만들지 않는다. |
| `409` 충돌 | 이미 다른 내용으로 확정되었음을 알리고 임의 재확정을 막는다. |
| `410` 만료 | 초안을 저장하지 않고 다시 문장을 입력해 새 초안을 만들도록 안내한다. |
| `422` 검증 실패 | 수정 가능한 필드에 오류를 표시하고 입력값을 유지한다. |
| 네트워크·서버 실패 | 저장 여부를 단정하지 않고 같은 키로 재시도할 수 있게 한다. |

## 접근성과 완료 확인

메시지와 초안 카드의 상태 변화는 텍스트로 표시하고 보조 기술에도 전달한다. 입력창, 예시 질문, 수정 폼, 확정 버튼은 키보드로 조작할 수 있어야 한다. 긴 답변도 작은 화면에서 가로 스크롤 없이 읽을 수 있게 한다.

1. 조회 답변에는 적용 기간·필터와 서버가 제공한 합계가 보인다.
2. 불완전한 요청은 추가 질문으로 이어지고 임의의 거래가 저장되지 않는다.
3. 초안 수정·확정 전에는 저장 완료 표현과 거래 목록 반영이 없다.
4. 확정 성공, 만료, 충돌, AI 장애를 서로 다른 상태로 안내한다.
