# 거래 목록·입력 UI 설계

이 문서는 [UI 공통 설계](ui-design.md)의 거래 화면을 구체화한다. 입력 필드와 경로는 [API 계약](../docs/api-contract.md)에 맞춘다. 직접 거래 등록은 채팅이 아닌 폼으로 처리한다.

현재 UI의 등록·수정·삭제는 브라우저 `localStorage`에 반영된다. 아래 HTTP 경로와 서버 오류 처리 규칙은 API 서버 연결 시 적용한다.

## 화면 구조

```text
거래 목록
├── 제목·거래 추가 버튼
├── 기간 / 유형 / 카테고리 필터
├── 적용 중인 필터 표시
├── 거래 행 목록·더 보기
└── 거래 입력·수정 폼 또는 삭제 확인창
```

데스크톱에서는 목록을 읽기 쉬운 표 또는 행으로, 좁은 화면에서는 날짜·유형·금액을 우선 보여주는 카드형 행으로 표시한다. 상세 항목은 같은 행 안에서 확인할 수 있어야 한다. 등록·수정 폼은 데스크톱에서 옆 패널이나 대화상자로, 모바일에서 전체 너비 화면으로 열 수 있다. 어느 배치든 필드 순서와 버튼 의미는 같다.

## 거래 목록과 필터

각 거래에 날짜, 수입·지출 유형, 금액, 카테고리, 사용처, 메모를 표시한다. 수정·삭제 행동은 해당 거래와 명확히 연결한다. 목록은 `GET /api/transactions`의 `from`, `to`, `type`, `category_id`, `limit`, `cursor`로 조회한다. 기간과 필터를 바꾸면 첫 페이지부터 다시 조회하고 적용 조건을 화면에 표시한다. `next_cursor`가 있을 때만 더 보기를 제공한다.

빈 목록에는 “조건에 맞는 거래가 없습니다”와 필터 해제 행동을 표시한다. 요청 실패를 빈 목록으로 오인하지 않도록 별도 오류와 재시도 버튼을 보여준다. 페이지 추가 요청이 실패해도 이미 표시된 거래는 유지하고 더 보기만 다시 시도할 수 있게 한다.

## 거래 입력 폼

목록의 `거래 추가` 버튼으로 한 화면에서 모든 필드를 확인하고 제출하는 폼을 연다. 키보드의 Enter 제출과 `거래 저장` 버튼은 같은 검증을 거친다. 입력 오류는 필드 옆에 표시하고 값을 보존한다.

| 순서 | 필드 | 입력 방식·규칙 |
| --- | --- | --- |
| 1 | 거래일 | 날짜 선택, 필수. 기본값은 Asia/Seoul 기준 오늘 |
| 2 | 유형 | 수입·지출 선택, 필수. 변경 시 카테고리 선택 재확인 |
| 3 | 금액 | 숫자 입력, 필수. 0보다 큰 원화 정수 |
| 4 | 카테고리 | 유형에 맞는 목록 선택, 필수 |
| 5 | 사용처 | 한 줄 텍스트, 선택. 수입에서는 지급처로 표시 가능 |
| 6 | 메모 | 여러 줄 텍스트, 선택 |

통화는 초기 버전에서 KRW로 고정하고 입력 필드를 두지 않는다. 카테고리 선택지는 `GET /api/categories`에서 받으며 로딩이나 실패 중에는 빈 선택지를 정상 목록처럼 보여주지 않는다. 취소는 요청 없이 폼을 닫고, `거래 저장`은 `POST /api/transactions`를 보낸다. 금액과 필수값을 제출 전에 검사하지만 최종 판정은 서버 응답을 따른다.

저장 중에는 중복 제출을 막는다. 저장된 거래가 서버에서 반환된 뒤에만 성공을 알리고 폼을 닫는다. 저장 실패 시 입력값과 폼을 유지한다. `422`의 필드 오류는 해당 필드에 연결하고, 그 밖의 오류는 폼 상단에 재시도 안내와 함께 표시한다. 저장은 성공했으나 목록 갱신에 실패한 경우 두 결과를 구분해서 알린다.

## 수정과 삭제

수정은 같은 폼에 기존 값을 채우고 버튼을 `변경 저장`으로 표시한다. 원본과 비교해 변경한 필드만 `PATCH /api/transactions/{id}`로 보낸다. 저장 성공 후 해당 거래와 월별 합계를 갱신한다. 서버가 `404`를 반환하면 이미 삭제된 거래일 수 있음을 알리고 목록을 다시 조회한다.

삭제는 별도 확인창에 날짜·금액·사용처를 보여준 뒤 `DELETE /api/transactions/{id}`를 보낸다. 성공 응답 전에는 거래를 목록에서 확정적으로 제거하지 않는다. 삭제 실패 시 거래를 유지하고 오류를 보여준다. 삭제 확인창에서는 취소가 기본적으로 안전하게 닫히며 키보드로도 조작할 수 있어야 한다.

## AI 초안과의 연결

[AI 도우미](assistant.md)에서 만든 초안을 사용자가 수정할 때도 이 폼의 필드 순서와 검증 방식을 쓴다. 다만 초안은 `POST /api/transactions`로 직접 저장하지 않고 초안 확정 경로로 보낸다. 확정 전에는 거래 목록과 대시보드 합계에 표시하지 않는다.

## 완료 확인

1. 거래 추가 버튼에서 폼을 열고 필수값·금액 오류를 필드별로 확인할 수 있다.
2. 직접 등록·수정·삭제의 성공과 실패가 구분되며, 성공 후 목록과 합계가 서버 결과와 일치한다.
3. 필터 변경과 더 보기가 현재 조건을 유지하고 중복 거래 행을 만들지 않는다.
4. 모바일 너비와 키보드만으로 필터, 입력, 수정, 삭제 확인을 완료할 수 있다.
