# 대시보드 UI 설계

이 문서는 [UI 공통 설계](ui-design.md)의 대시보드 화면을 구체화한다. 데이터 계약은 [API 계약](../docs/api-contract.md)을 따른다. 현재 목 UI는 브라우저 메모리의 샘플 데이터로 이 구조를 보여주며 실제 API 요청은 후속 작업이다.

## 화면 목적과 진입

앱의 첫 화면이다. 사용자가 선택한 월의 수입, 지출, 차액과 카테고리별 지출을 한눈에 확인한다. 차액은 `수입 − 지출`이고 계좌 잔액이라는 표현을 쓰지 않는다. 기본 월은 Asia/Seoul 기준 현재 월이다.

## 화면 구조

```text
대시보드
├── 화면 제목·월 선택
├── 수입 / 지출 / 차액 요약 카드
├── 카테고리별 지출 목록
└── 거래 목록으로 이동
```

| 영역 | 표시 내용 | 사용자 행동 |
| --- | --- | --- |
| 상단 | `대시보드`, 현재 선택 월 | 이전·다음 월 또는 월 선택 |
| 요약 카드 | 수입, 지출, 차액을 각각 원화로 표시 | 금액과 의미 확인 |
| 카테고리별 지출 | 카테고리 이름, 금액, 전체 지출 대비 비중 | 수치 비교 |
| 하단 이동 | 선택 월 거래 보기 | 거래 목록으로 이동하고 월 조건 전달 |

데스크톱에서는 요약 카드를 한 행에 배치한다. 좁은 화면에서는 카드와 카테고리 목록을 한 열로 쌓는다. 비중을 막대나 차트로 그리더라도 이름과 금액을 텍스트로 함께 제공한다. 지출이 0원이면 비중 계산을 생략하고 `0원`만 보여준다.

## 데이터와 상호작용

월을 선택하면 `GET /api/summary?month=YYYY-MM`을 호출한다. 반환된 `income_total`, `expense_total`, `difference`, `expenses_by_category`를 화면에 표시한다. UI에서 서버 합계를 재계산하거나 AI 답변의 금액으로 덮어쓰지 않는다. 원화 정수는 천 단위 구분자와 `원`을 붙여 표시한다.

월 이동 직후에는 선택 월을 먼저 표시하고 해당 월의 조회 상태를 보여준다. 이전 월 요청이 늦게 도착해도 더 최근에 선택한 월의 결과를 덮어쓰지 않는다. 거래 등록·수정·삭제 또는 초안 확정 후 현재 월의 합계를 다시 조회한다. 거래 목록 이동 시 선택 월을 전달하되, 새로고침 후 월 선택을 보존하는 기능은 초기 범위 밖이다.

## 상태별 표시

| 상태 | 화면 처리 |
| --- | --- |
| 첫 로딩·월 변경 | 선택 월과 요약 영역의 로딩 상태를 표시한다. 이전 월 수치를 현재 월 결과처럼 표시하지 않는다. |
| 거래 없음 | 수입·지출·차액 `0원`, “이 달에 기록된 거래가 없습니다”와 거래 추가로 가는 행동을 표시한다. |
| 조회 실패 | 금액을 확정값처럼 표시하지 않고 오류 설명과 재시도 버튼을 제공한다. |
| 일부 카테고리 없음 | 서버가 반환한 항목만 표시하며 없는 항목을 임의로 채우지 않는다. |

로딩·오류 메시지는 화면에 보이고 보조 기술에도 전달되게 한다. 색상만으로 수입과 지출을 구분하지 않는다.

## 완료 확인

1. 초기 진입 시 Asia/Seoul의 현재 월이 선택되고 서버 집계가 표시된다.
2. 월을 빠르게 연속 변경해도 마지막에 선택한 월의 값만 남는다.
3. 거래가 없는 월과 조회 실패가 서로 다른 상태로 표시된다.
4. 저장 성공 후 선택 월의 합계가 갱신되고 서버 응답과 일치한다.
