# 서버 없는 목 UI 개발 환경

이 문서는 화면 구현 전에 개발 컨테이너의 실행 경로와 데이터 경계를 정한다. 현재 `ui/` 프로젝트와 화면 코드는 없으며, 이 문서를 추가해도 UI가 자동으로 생성되거나 실행되지는 않는다. 화면별 구성은 [UI 공통 설계](ui-design.md)에서 시작한다.

## 개발 컨테이너

GitHub Codespaces 또는 Dev Containers로 저장소를 열면 `.devcontainer/devcontainer.json`이 Python, Git, Node.js 24, npm을 사용할 수 있는 환경을 준비한다. Vite 개발 서버용 `5173` 포트를 전달한다. 컨테이너 생성 뒤에는 Git 명령, Python 테스트, 문서 검증이 실행된다. 이 단계에서는 `ui/`가 없으므로 npm 설치나 개발 서버 시작을 자동으로 실행하지 않는다.

## 목 UI를 구현할 때의 실행 계약

향후 `ui/`에 React·TypeScript·Vite 프로젝트와 잠금 파일을 만든 뒤, 개발 컨테이너 터미널에서 다음 명령으로 시작한다. `npm ci`는 해당 프로젝트의 의존성과 잠금 파일이 준비된 후에만 실행한다.

```bash
npm --prefix ui ci
bash scripts/run_mock_ui.sh
```

실행 스크립트는 `0.0.0.0`에 바인딩하고 고정 포트 `5173`을 사용한다. 포트가 이미 사용 중이면 다른 포트로 이동하지 않고 오류를 확인한다. Codespaces에서는 전달된 포트의 정확한 호스트 이름만 Vite에 추가로 허용한다. 로컬 개발 컨테이너에서는 기본 허용 호스트를 사용한다. `ui/package.json`이 없으면 스크립트는 UI 프로젝트가 아직 없다고 안내하고 종료한다. 현재 `docker compose up`은 문서 검증만 실행하며 목 UI 서버를 시작하지 않는다.

## 데이터와 동작 경계

- 첫 목 UI는 브라우저 안의 고정된 샘플 데이터로 대시보드, 거래 목록, 입력 폼, AI 도우미의 화면 상태를 재현한다. API 서버, DB, OpenAI, 서비스 토큰은 필요하지 않다.
- 화면에서 쓰는 목 응답의 필드와 상태는 [API 계약](../docs/api-contract.md)을 기준으로 한다. 정상 결과뿐 아니라 빈 목록, 입력 오류, 로딩, AI 장애, 초안 만료도 표현한다.
- 목 데이터 접근을 화면 컴포넌트 밖의 교체 가능한 경계에 두어 나중에 실제 `/api` 호출로 연결할 수 있게 한다. 목 모드에서는 실수로 `/api`에 요청하지 않도록 한다.
- 개발 중 직접 입력·수정·삭제와 초안 확정은 화면 상태를 시험할 수 있지만, 새로고침 후 영속성이나 실제 서버 저장을 약속하지 않는다. 화면에는 목 데이터임을 알 수 있게 표시한다.
- shadcn/ui 등 UI 패키지는 화면 구현 단계에서 선택·설치한다. 이 환경 구성 단계에서는 npm 패키지를 추가하지 않는다.

## 완료 확인

1. 개발 컨테이너에서 `git`, `node`, `npm`, `pytest` 명령이 실행된다.
2. UI 프로젝트가 만들어진 뒤 Vite가 `5173` 포트에서 실행되고 Codespaces 전달 포트로 접근된다.
3. API 서버가 없는 상태에서 화면의 기본·빈 결과·오류 상태를 확인할 수 있다.
4. 목 모드에서 외부 API나 비밀값에 의존하지 않는다.
