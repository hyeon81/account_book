# 가계부 UI 공통 설계

초기 로컬 단일 사용자 가계부의 UI 문서 시작점이다. 화면별 구조와 세부 동작은 아래 문서에 나누어 정의한다. 시스템 경계는 [전체 설계](../docs/agent-account-book-design.md), HTTP 요청·응답은 [API 계약](../docs/api-contract.md), 코드와 테스트 배치는 [개발 규칙](../docs/development-rules.md)을 따른다. 현재 UI 코드는 없으며 이 문서들은 구현 기준이다.

| 페이지 | 사용자 목표 | 세부 문서 |
| --- | --- | --- |
| 대시보드 | 월별 수입·지출·차액과 카테고리별 지출 확인 | [대시보드 UI](dashboard.md) |
| 거래 목록·입력 | 거래 조회·필터·직접 등록·수정·삭제 | [거래 목록·입력 UI](transactions.md) |
| AI 도우미 | 자연어 질문과 거래 초안 검토·확정 | [AI 도우미 UI](assistant.md) |

서버 없이 화면 상태를 먼저 구현할 때의 개발 컨테이너와 데이터 경계는 [목 UI 개발 환경](mock-ui-development.md)을 따른다.

## 공통 탐색과 레이아웃

데스크톱에서는 상단 또는 왼쪽 탐색에서 세 페이지를 오간다. 좁은 화면에서는 한 페이지씩 보여주고 탐색 항목과 주요 버튼을 쉽게 누를 수 있게 배치한다. 각 페이지의 제목과 현재 위치를 분명하게 표시한다. 입력 중인 값과 월·필터 선택은 페이지를 잠깐 오가더라도 유지하되, 새로고침 이후 복원은 초기 범위에 넣지 않는다.

금액은 원화 정수로 표시하고 거래일은 Asia/Seoul 기준 현지 날짜로 다룬다. 차액은 `수입 − 지출`이며 실제 은행 잔액으로 표현하지 않는다. 초기 버전에는 로그인, 다중 사용자 전환, 영수증 업로드, 은행 연동을 넣지 않는다.

## UI 기술과 경계

React, TypeScript, Vite로 화면을 구성하고 UI 컴포넌트는 shadcn/ui를 기준으로 구현한다. 빌드된 화면은 Nginx가 제공하며 브라우저는 같은 출처의 `/api`만 호출한다. 브라우저 코드에 Compose 내부 서비스 주소, DB 연결 정보, OpenAI 키, 내부 서비스 토큰을 넣지 않는다. 공통 버튼·입력·카드·대화상자는 화면별로 중복 구현하지 않고 재사용한다.

도메인 계산과 거래 저장 판정은 API 서버가 맡는다. UI의 로컬 상태는 선택한 페이지, 필터, 폼 입력, 로딩·오류·성공 표시를 담당한다. 서버의 오류 응답은 [API 계약](../docs/api-contract.md#오류-응답)의 `error.code`를 기준으로 필드 또는 페이지 메시지에 연결한다. 저장 성공과 실패를 같은 색이나 문구로 표현하지 않는다.

## 공통 접근성 기준

- 모든 입력에 보이는 레이블을 붙이고 필수 여부와 오류를 텍스트로 전달한다.
- 키보드만으로 탐색, 필터, 거래 입력, 초안 확인을 완료할 수 있어야 한다.
- 대화상자를 열면 포커스를 내부로 옮기고 닫으면 원래 버튼으로 돌린다.
- 로딩 완료, 저장 결과, 입력 오류는 화면에 보이고 보조 기술에도 전달되게 한다.
- 수입·지출과 성공·실패를 색상에만 의존해 구분하지 않는다.

## 구현과 검증 범위

초기 구현은 각 화면 문서의 완료 확인 항목을 기준으로 검증한다. 문서 자체의 링크·코드 블록 검사는 저장소 루트에서 `python scripts/validate_docs.py`로 실행한다. 이 검사는 실제 UI 기능이나 접근성을 증명하지 않으므로 구현 단계에서 화면·키보드 동작을 별도로 확인한다.
